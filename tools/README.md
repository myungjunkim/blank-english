# tools

## check.js — 문장·발음 데이터 검사기

```
node tools/check.js
```

문장을 더하거나 발음을 손본 뒤에는 **커밋 전에 반드시** 돌립니다.
오류가 있으면 종료 코드 1로 끝나므로 자동화에도 걸 수 있습니다.

결과는 두 갈래입니다.

| | 뜻 |
|---|---|
| **오류** | 반드시 고쳐야 합니다. 앱이 잘못 동작합니다. |
| **확인** | 사람이 판단할 것. 일부러 그렇게 둔 경우도 있어 0건이 목표는 아닙니다. |

### 무엇을 보는가

**문장**
- id 중복, 빈 필드, `CATEGORY_NAMES`에 없는 카테고리
- 빈칸이 문장당 하나인지
- 정답을 끼웠을 때 공백·구두점이 깨지지 않는지
- 힌트에 정답이 그대로 들어 있지 않은지
- 정답이 빈칸 폭보다 길지 않은지
- 한 카테고리 안에서 정답·영어 문장이 겹치지 않는지
- 한국어가 완전히 같거나 거의 같은 쌍 (편집거리 2 이내)

**채점**
- 정답 후보 전부와 그 변형(대소문자, 앞뒤 공백, 굽은 따옴표)이 통과하는지

**발음**
- 문장에 쓰이는 낱말에 발음이 다 있는지
- 한글 발음이 빈 채로 나오지 않는지
- 강세 표시 범위가 글자 수를 벗어나지 않는지
- `pron`의 대괄호 짝이 맞는지
- 2음절 이상인데 강세 기호가 없는지
- 철자와 발음이 어긋나 보이는지 (th 유·무성 등)

**파일**
- 한 파일 안에 LF와 CRLF가 섞이지 않았는지
  (윈도우에서 git이 체크아웃할 때 파일 전체를 CRLF로 바꾸는 것은 정상입니다.
   두 가지가 섞이는 것만 문제 삼습니다.)
- `sw.js`의 캐시 목록에 주요 파일이 다 있는지

### CMU 발음사전과 대조 (선택)

사전 API에서 받은 발음에 오류가 없는지 별도 자료와 견줍니다.
`within`이 `wɪˈθɪn`(무성)으로 들어와 「위씬」이 되던 일을 이걸로 찾았습니다.

```
curl -sLo tools/cmudict.dict \
  https://raw.githubusercontent.com/cmusphinx/cmudict/master/cmudict.dict
node tools/check.js --cmu tools/cmudict.dict
```

CMU는 미국식, 우리 데이터는 영국식이 섞여 있어 r 관련 차이가 많이 나옵니다.
자음이 다르다고 다 오류는 아니므로 하나씩 봐야 합니다.
`cmudict.dict`는 용량이 커서 저장소에 넣지 않습니다.

### 검사기가 앱의 코드를 그대로 쓰는 이유

채점(`isCorrect`)과 발음 변환(`ipaToHangul`, `readPron`)은
`index.html`에서 함수를 떼어 와 그대로 돌립니다.
검사기가 따로 구현하면 앱이 바뀔 때 검사기와 어긋나
"검사는 통과하는데 앱은 틀리는" 상태가 되기 때문입니다.
